# WeBox 1.0 设计与验收方案

发布日期目标：2026-07-29  
范围：仅 macOS 13+、仅管理本机微信应用副本。

## 产品目标

让用户能可靠地创建、检查、启动、关闭、删除和恢复多个本地微信实例。WeBox 不读取聊天内容、不修改微信协议、不迁移账号数据，也不提供 Windows、Linux 或移动端版本。

## 1.0 功能边界

| 能力 | 1.0 交付 |
| --- | --- |
| 实例生命周期 | 创建、启动、关闭、删除、批量启动、批量关闭 |
| 完整性 | 检查应用路径、Bundle Identifier、代码签名和原版微信版本；给出可理解的异常状态 |
| 恢复 | 对未运行实例修复 Bundle Identifier 与 ad-hoc 签名；缺失副本保留记录并标为异常 |
| 管理界面 | 纵向紧凑列表、搜索筛选、状态摘要、主窗口和状态栏入口 |
| 隐私与诊断 | 数据仅本机 SQLite；用户可查看或复制不含账号内容的诊断信息 |
| 发布 | 可重复的 arm64/macOS 13+ DMG 构建、签名校验、校验和和 GitHub Release |

## 明确不交付

- 不读取、同步、迁移或备份微信账号与聊天数据。
- 不承诺绕过 macOS、微信客户端或服务条款限制。
- 当前没有 Apple Developer ID 证书，因此发布包是 ad-hoc 签名，不能实施安全的自动下载/安装更新。
- “检查更新”只显示并打开公开 Release；正式自动更新须在 Developer ID 签名、公证和独立更新签名就绪后实施。

## 关键交互

1. 启动时自动刷新实例运行状态和原版微信版本；用户也可点击“检查全部”。
2. 若实例副本缺失、标识符不匹配或签名无效，显示“异常”及原因，并提供“修复”操作；运行中的实例不自动改写。
3. 列表支持名称搜索与状态筛选。批量操作仅影响当前可见实例，关闭操作会忽略已停止实例。
4. 删除先停止进程，再移入废纸篓，最后删除数据库记录；任何一步失败都报告具体原因。
5. 诊断报告只含版本、实例状态、路径、Bundle Identifier 和签名/版本检查结果，不含微信账号、消息或文件内容。

## 验收标准

- 单元/组件验收覆盖：实例模型、Bundle ID 唯一规则、SQLite 增删改查、复制、健康检查和批量操作选择逻辑。
- 自动验收脚本能编译核心模块、运行离线测试、构建 DMG，并以 `codesign --verify --deep --strict` 检查应用包。
- 人工验收：创建两个中文名称实例；分别启动、关闭、删除并重新创建；原版微信升级后显示“需要更新”；损坏签名后能检测且在未运行时修复。
- 发布验收：公开 GitHub Release 包含 DMG、SHA-256 和发布说明；README 写明版权、版本、许可证与微信相关权利边界。

## 风险与回滚

- 创建、修复和删除只操作用户选中的副本；创建失败会清理新建副本，删除使用废纸篓。
- 修复会改写副本的 `Info.plist` 并重新签名，因此运行中的实例只标记待处理，不自动修复。
- 所有数据库变更在单条 SQLite 写入中完成；副本遗失时保留记录，便于用户确认后删除或恢复。
